Example document for a **pickup-ready** task. Delete it with the other example rows and

## The test this document has to pass

**A stranger opens this file, having never seen the conversation that produced it, and
can start working.** That stranger might be another agent, a teammate, or an unattended
scheduled run. If they would have to ask you a question first, the task is not
pickup-ready — whatever the table says.

That is the whole reason ⏳ means *pickup-ready* and not merely *not started*.

## What needs to happen

The work itself, concretely. Not "improve the settings page" — say which page, which
fields, what they persist to, and what the user should be able to do afterwards that
they cannot do now.

## Acceptance criteria

List them as things that can be checked, one per line. If you cannot write these, the
task is not ready to be picked up and the honest move is to say so in this section
rather than leave the row sitting at ⏳.

## Why, not just what

The reasoning is the part worth the most in six months, and the part a commit message
never captures. Include the approaches you considered and rejected — a future session
that does not know why an obvious-looking option was ruled out will spend an afternoon
re-discovering it, then quite possibly ship it.

## Files, paths, commands

Name every file the work touches, the command that runs the tests, and any gotcha that
would otherwise be re-derived. Depth costs nothing here: this document is loaded on
demand and never at boot, which is the entire point of keeping it out of the ledger.

## Claiming it

When you start, move the row to 🔄 and put your roster name and short session id in the
table's `Owner` cell. Before taking a row someone else already owns, check
`.session_debt.tsv`: a recent row for that session id means they are still working —
pick another. No recent row means the claim is stale and it is yours to take.
